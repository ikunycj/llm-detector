# 数据来源与执行位置

## 统一页面

不再切换本地 / 云端工作区。所有列表合并展示浏览器、已登录云端及浏览器中配置的自建 Worker 数据，每条记录标明来源。内部以 `来源 ID + 记录 ID` 区分记录；渠道报告还包含项目 ID，避免不同服务的同名渠道或相同 ID 混淆。

云端地址固定为当前站点，登录按需弹出，只需输入服务端 `.env` 的 `APP_LOGIN_KEY`。登录态使用服务端的到期时间并在当前浏览器保留，默认 `SESSION_TTL=24h`。登录、退出不会删除浏览器配置，也不会把本地数据自动上传。某个 Worker 无法访问时显示该来源的错误，其他来源正常显示。

## 保存

模型 API 的添加、编辑、批量导入、项目连接、巡检计划、渠道协议、渠道密钥都使用统一的位置选择弹框：

- **浏览器本地**：模型 API 存于 localStorage，项目快照和历史存于 IndexedDB。
- **云端**：登录后存入当前账号的 SQLite。
- **自建 Worker**：存入用户选择的 Worker 的 SQLite。

相同来源的编辑会更新原记录；选择其他位置会创建副本，原记录保留。复制项目时包括渠道、密钥和计划配置，不复制历史批次；副本的定时计划默认关闭，用户保存设置明确启用后才调度。

普通列表不会返回云端或 Worker 中已保存的明文 Key。只有用户确认跨位置保存或执行后，浏览器通过认证的 transfer 接口取得本次操作所需凭据，转交目标。凭据不显示在页面或日志中，只有选“浏览器本地保存”才长期保存在浏览器。

浏览器保存项目连接不依赖云端；填写 User ID 可直接保存，管理员账号/邮箱解析需由本机 Worker 访问 New API。密码与验证码不持久化。

## 执行

点击巡检、指纹检测、Terminal Bench、项目手动/批量巡检、同步渠道或模型发现时，弹框选择 **本地 / 云端 / 自建 Worker**。取消不发起任务。

| 操作 | 本地 | 云端 / 自建 Worker |
| --- | --- | --- |
| Fingerpoint | 浏览器直接调用供应商 API 和 shared detector | 所选服务中的 Go SDK |
| Terminal Bench | 本机 Worker 调用 Harbor / Docker | 所选服务调用 Harbor / Docker |
| New API 同步、密钥导入、项目批次 | 本机 Worker 直连项目/渠道，快照保存回浏览器 | 在所选服务执行和保存 |
| 定时计划 | 浏览器不支持离线调度 | 在保存计划的服务中调度 |

执行结果保存到执行位置，页面统一拉取。跨位置项目操作会在目标创建项目副本。本地任务不会自动转发到云端。浏览器直连模型要求供应商允许 CORS。

## 两种 Worker

- **本机执行 Worker（9002）**：`cmd/local-runner`，只监听回环地址，网页自动发现并建立来源绑定会话。项目配置和历史仍在浏览器，本机临时目录在任务或会话结束后清理。
- **自建 Worker（默认 9003）**：`cmd/worker`，需要用户提供地址和密钥。可运行在本机或服务器，独立加密 SQLite 持久化，不使用云端账号系统。

它们复用同一应用运行时、模型协议和引擎注册表。自建 Worker 的连接清单（包括访问密钥）只在当前浏览器保存。移除连接不删除 Worker 数据。

安装与部署步骤见 [worker.md](worker.md)。

## 数据库

云端和每个自建 Worker 均使用 `internal/cloud/schema.sql` 初始化自己的数据目录。现有 `documents` 按 kind/id 保存加密 JSON，新增 Worker 不改变表结构，无需数据库迁移。自建 Worker 拒绝使用已有多用户云端数据库。`cloud.key` 必须与同目录 SQLite 一起保留，丢失时不会生成替代密钥。

## 云端密钥与原有数据

云端像地址预设的 Worker：持有 `APP_LOGIN_KEY` 的访问者登录到 `CLOUD_ADMIN_USERNAME` 指定的数据账号。浏览器不再填写账号或密码，服务端仍复用原账号 ID 和加密 SQLite 数据，不迁移、不覆盖原数据。`CLOUD_ADMIN_PASSWORD` 仅用于全新数据库创建内部账号，不是网页登录凭据。现有会话继续按各自到期时间生效。

位置弹框进入 Worker 配置或安装页面时隐藏；关闭配置页后恢复待处理选择，新增 Worker 成功后默认选中它，仍需确认最终保存或执行。
