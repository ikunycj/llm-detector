# 巡检日志

顶部导航中的「巡检日志」统一展示原来分散在首页「巡检结果」、项目巡检「任务日志」、指纹检测「历史指纹任务」和 Terminal Bench「运行记录」中的数据。原页面保留配置与启动操作；指纹页仍显示当前一轮的实时样本与排名。

## 筛选与详情

- 默认按创建时间倒序，每 3 秒刷新。
- 可以组合筛选任务类型、模型服务 / 项目、引擎、状态和保存位置；关键词支持模型 ID / 名称、服务、项目、渠道名称和任务 ID。
- 模型巡检详情保留各模型检查、错误和输出证据。指纹详情包含历史提示词、回复、数字数量、耗时与完整候选列表；旧记录未保存的证据不会补造。
- 项目批次详情列出渠道和引擎，展开渠道行查看模型结果。
- Terminal Bench 详情展示逐题进度、Reward、错误及结束时间，并允许取消仍在运行的任务。
- 启动项目巡检后直接打开对应批次；首页与引擎页完成提交后提供日志跳转。

## 数据合并

页面沿用已有的 scans、inspection/runs 和 terminal-bench/jobs 数据接口及本地存储，不改变存储结构、保留期限或登录权限。浏览器本地、已登录的云端和已配置的 Worker 一并加载；某种记录或来源读取失败时显示原因，其他成功加载的日志继续可见。

记录身份由「类型 + 来源 + ID」组成，不会合并不同 Worker 上相同的 ID。指纹历史本身属于模型巡检记录；项目批次通过 scan_id / result.id 关联子扫描，模型结果通过 Terminal Bench 报告内的 job ID 关联运行任务。有明确关联的子记录归入同一个详情，不重复出现在顶层列表。没有关联信息的任务独立保留，不根据时间、模型名或服务名猜测关联。

状态沿用原任务语义。「已完成」不等于模型身份已确认；指纹结论和能力测试结果应在详情中分别查看。
